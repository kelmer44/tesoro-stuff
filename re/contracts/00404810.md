# 00404810 — inferred_ScriptBlock_Parse
Status: emu-compared · Cluster: 10 · Convention: thiscall(ScriptBlock *this, FILE *file) — RET 8 (the second slot is unused garbage from the caller)

**Purpose (confirmed):** Reads one script block (the text after a leading '.') from a .DLG file into a 0xd8 byte block object and compiles its commands into 24 byte entries. This is the whole script compiler: the scripts are plain text, nothing is binary.
**Text format (from the shipped ANIMS/CONVERS/ICONS/OBJETOS.DLG, CR LF lines, CRT stdio reads with fscanf):**
- Header: `.NAME [type]` (name read with %s, key = NameHash64; a space after the name means a number follows, the block's *type*, else 0); next line the number of characters, then that many lines with a character name each (keys kept in order; a digit in a sendmessage picks one, '1' is the first). Type 1..21 selects the native routine behind the block's `DO` lines (one block per type: FANPRESENT 1, FANCAMAROTE 2, FANEMBARKE 3, FANMOTIN 4, FANMLGISLA 5, FANPLAYA 6, FEXPLOSION 7, CONV33 8, FSALPANTA 9, CONV31 10, CONV34 11, CONV35 12, CONV36 13, FCONECTA 14, FIXCUERDA 15, FBARCO 16, FANMMENU 17, FANLUCHDICK 18, FFINAL 19, FANMTRONO 20, FCAPITAN 21); the others are 0.
- Then one command per line, chosen by the first character (any other character is an error: message box "ERROR AL LEER COMANDO" and the parser returns early). After a command the rest of the line is skipped (so `//` comments after commands are ignored). The block ends at a line starting with '.', after which one more line (blank) is skipped.
- ` <phrase>, <n>[, <m>]` (line starts with a space): op 1, [+4] = a reference to the spoken line from 0x413940 (looked up by name in the four speech tables, now ported: contract 00413940), [+8] = n, [+0xc] = m or 0. Most of the 2224 lines in the shipped files.
- `_label`: not an entry; adds a label (key, index of the next entry). `return`: op 0. `.`: op 10 (closes the block). `break`: op 3. `sleep n`: op 2, [+4] = n ms. `jmp label`: op 4, [+4/+8] = label key. `if vN == V jmp label`: op 7, [+4/+8] label key, [+0xc] = N, [+0xd] = V (bytes). `vN = V`: op 0xb, [+4] = N, [+5] = V (the original reads both as 32 bit integers into overlapping addresses, so [+6..+8] receive sign filler). `DO text`: op 0xc, [+4] = ordinal (0, 1, 2 ... counted per block in file order; the text after DO is only a comment). `run 'BLOCK' label`: op 8, [+4/+8] block key, [+0xc/+0x10] label key.
- `play avi N` op 0xd ([+4] = N), `play cd N` op 0xf ([+4] = N), `play sound 'NAME'` op 0xe ([+4..] = the name as text, NUL ended, at most 20 bytes); other `play` words add nothing.
- `menu`: op 5. `menuitemN [next] [vV | !vV]` (any word of more than three letters after the m, the 'n' of the second word marks a following item): op 6, [+4] u16 = 1 if the second word starts with n else 0, [+6] = variable V (0xff if no condition), [+7] = 1 for '!v'. The shipped files also contain the typo 'menutiem0'. The item's own text is the phrase line right after it.
- `sendmessage <target> [in <level>] <order>`: op 9. Target: `'NAME'` (key at [+4/+8]) or a digit (the character of that number). `in INVENTARIO` or `in LEVELn` put a level reference at [+0xc] (0 = the script's own level). Order at [+0x10]: `play x y word` = 0 ([+0x14] first frame, [+0x15] last frame, [+0x16] word: stop 0, play 1, loop 2, wait 3), `ira x y` = 1 (walk, [+0x14]/[+0x16] shorts), `mirar ARRIBA|ABAJO|IZQUIERDA|DERECHA` = 2 ([+0x14] 1..4), `activate on|off` = 3 ([+0x14] 0/1), `show on|off` = 4 ([+0x14] 0/1).
**Numbers** are read with %i (decimal, 0x hex, leading 0 octal; a sign is allowed).
**Outputs / state written:** block key (+0x44/+0x48), type (+0xd4), character count (+0xb8) and keys (+0xb4, 8 bytes each), entries (+0xbc, count +0xc0), labels (+0xc4, 12 bytes each, count +0xc8). The first byte after the name is used to detect the type, so a name must be followed directly by a space or the end of line.
**Calls:** fscanf (0x41c120), sscanf (0x41bf50), NameHash64 0x415c40, phrase lookup 0x413940, getc/ungetc, the pool allocator 0x40db40, MessageBoxA on errors. **Caller:** 0x406190 (once per block).
**Edge cases:** Unwritten bytes of an entry are stack garbage in the original (never read). Stale scratch variables survive a failed number read within the same block. The scratch array limits a block to about 300 entries.
**Port:** engines/tesoro/core/scriptblock.{h,cpp}::ScriptBlock::parse (private, used by ScriptLibrary::load); the text reader ScriptText mimics the stdio calls used. ScriptLookup supplies the phrase numbers and the level references that the original takes from live objects.
**Validation:** Differential check `re/tools/run_startup_check.sh` (gen_vectors_dlg.py + drivers/dlg_driver.cpp): the original loader 0x406190 (with the parser 0x404810 and the resolver 0x406110) runs in Unicorn on the four shipped script files (145 blocks), on a synthetic file (octal and hex numbers, "in LEVELn", run FANMTRONO, play sound/cd/avi) and on 500 randomly edited real blocks (characters deleted, replaced, inserted, lines duplicated). The CRT file calls are hooked onto an in-memory text; the phrase lookup 0x413940 is replaced by a keyed formula. The commands live in a stack array that the parser never clears, so unwritten bytes are found by running twice with different stack fills (refilled before each block and each command) and only bytes equal in both runs are compared. Result 30 Oct 2026: compiler 517/517 blocks (369312 bytes of commands), resolver 517/517, 32/32 randomly broken texts rejected by both. Mutations caught: ordinal off by one, label position off by one, menu 'next' flag, menu chain start, menu condition bytes, if-variable and value bytes, run block index and label shift, FANMTRONO special case, INVENTARIO and LEVELn references, sendmessage play mode / show / walk / look fields, the phrase line fields, hex and octal numbers, signs, set matching. Three survive because no data reaches them: the exact end-of-file boundary (<= instead of <), whitespace before the word in "in <level>" (the %s skips it) and the second letter of 'return' being copied into the end-of-line test. Not covered: the real phrase lookup (0x413940 searches live levels), texts cut off in the middle of a command (the original rereads a stale byte), lines longer than the scratch buffers.
**Open questions:** What 0x413940 (and its callee 0x4138b0) searches exactly; which native routine each type runs for its DO lines (only type 17 read).
