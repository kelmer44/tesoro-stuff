# 0040f800 — inferred_List_PushBack
Status: emu-compared · Cluster: 28 · Convention: thiscall(List *this, value) — RET 4

**Purpose (confirmed):** Appends a value to the list.
**Outputs / state written:** rewinds, walks the whole list with the cursor, then inserts a node after the cursor (the last node). The node is taken from the free list if it has one, otherwise from the block's bump pointer. The cursor is left on the last node (before the new one), the value slot holds the last element seen.
**The walk (inlined in every list function):** step: next := cursor.next; if next == 0 stop (no element). If cursor is the head and the at-start flag is set, clear the flag and stay; otherwise cursor := next. If cursor.next == 0 stop. Otherwise the value slot := cursor.next.value and the element is cursor.next. So the cursor always rests on the node before the current element.
**Calls:** none
**Edge cases:** no capacity check (see List_Ctor). Callers: 00407b80, 0040f210, 00410330, 00413e60 and others.
**Port:** CursorList::pushBack, step. **Validation:** Differential check `re/tools/run_startup_check.sh` (gen_vectors_list.py + drivers/list_driver.cpp): the original list code run in Unicorn on real list memory (pool allocator replaced by a zeroing bump allocator) with 600 random operation sequences of 2-40 operations (capacity 1-14, repeated and unique values, negative priorities), each followed by a full dump of the chain and the cursor's data slots, vs engine CursorList: List state 5876/5876, List remove result 1448/1448, ObjectList state 6865/6865, RemoveByObject result 1867/1867, EndFrame result 966/966. The port was first a linked list in an array, then rewritten as a plain array with a cursor index; both versions pass every comparison. Four of five deliberate mutations of the first version were caught (one by hanging), and all five of the array version. Not covered: the cursor's start flag after Clear (every operation rewinds first, so nothing here can see it), stepping after Remove without a rewind (no such function exists; only inlined copies in other classes), node pool exhaustion, lists sharing one pool (Ctor with a source list), FindByKey (predicate search; not run in the emulator), the ObjectList cursor position (the generator only probes the List cursor, with the insert-after-cursor function).
