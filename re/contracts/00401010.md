# 00401010 — inferred_AnimBank_ScaleBrightness
Status: understood · Cluster: 1 · Depth: 1 · Convention: thiscall(AnimPlayer *this, uint32 factor) — RET 4; only the low 16 bits of factor are used; allocates a 0x1040 byte frame (chkstk 0041b3c0)

**Purpose (confirmed):** Multiplies the brightness of every literal-pixel image of the bank by factor/256 in place.

**Inputs:** factor (u16, 256 = unchanged); this+0 image pointer array, this+0x20 image count; per image: +0 pixel data pointer, +4 pixel data byte size, +0xc u16 type; display flag byte at (global 00442108)+0x67c (0: 5-6-5 pixels, nonzero: 5-5-5 pixels).
**Tables built:** low[i] = ((i * f) >> 8) for i in 0..31 (u16, **not clamped**); high[j] for j in 0..0x7ff: g = min(((j & 0x3f) * f) >> 8, 0x3f), r = min(((j >> 6) * f) >> 8, 0x1f) (clamps compare the low 16 bits unsigned), high[j] = ((r << 6) | g) << 5.
**Outputs / state written:** for each image index 0..count-1 whose type == 1: for each of size/2 16-bit pixels p:
- 5-6-5 mode: p' = high[p >> 5] | low[p & 0x1f].
- 5-5-5 mode: q = ((p & 0xffe0) << 1) | (p & 0x1f) (16 bit); v = high[q >> 5] | low[q & 0x1f]; p' = (v & 0x1f) | ((v >> 1) & 0x7fe0).
Other image types are untouched.
**Calls:** chkstk only.
**Yields / blocks / timing:** none
**Edge cases:** blue (low) channel is not clamped: with factor > 256 the product exceeds 31 and spills into the green bits through the OR (red and green are clamped). No null check on image pointers: a deferred (mode 2) bank whose images are not loaded would crash. Image data are modified once per call, so repeated calls compound.
**Evidence:** asm 00401010-00401158 (the decompile is garbled by the stack frame); loops at 0040111b (565) and 004010d0 (555).
**Port:** engines/tesoro/core/animimage.cpp::BrightnessTable + AnimImage::scaleBrightness, driven by AnimBank::scaleBrightness. Deviations: images that are not loaded are skipped (the original would crash); pixel ranges are clamped to the blob.
**Validation:** Differential check `re/tools/run_startup_check.sh` (gen_vectors_anim.py + drivers/anim_driver.cpp): original Load/LoadImage/LoadDeferredImages/ScaleBrightness/SetRange run in Unicorn (fread/fgetpos/fseek/fsetpos, Archive_SeekEntry, the pool allocator and Clock_Now replaced by Python) on 700 synthetic animation files (0-9 sequences of types 0/1/2/4, 0-5 images of types 0/1/2/3/7, both pixel layouts, 5-5-5 and 5-6-5, load modes 0 and 2) vs engine AnimPlayer/AnimBank/AnimImage: load 700/700, header 700/700, flags 700/700, sequences 2509/2509, image positions 700/700, images after load 1396/1396, after deferred load 861/861, after brightness 832/832, SetRange 1748/1748. Five deliberate mutations of the port were all caught. Limits: synthetic data only (the shipped .DAT was not read); pool allocation/exhaustion is not modelled; the 5-5-5 overrun past the blob end and a sequence-less bank with images are not reproduced; pixel-first layouts are tested only without 5-5-5; item arrays shared by two spans are not tested; ranges reading past the sequence table are not tested.
**Open questions:** who calls it and with which factor (no code caller in the ledger xrefs: possibly a data slot); where the 555/565 flag at +0x67c is set.
