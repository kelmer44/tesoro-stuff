# 004112d0 — Display_QueueRow_Mask (shadow images, type 2 and any other type but 1 and 3)
Status: emu-compared · Cluster: 31 · Convention: 7 stack args (image row entry, mask row block, count, x, depth, clip, extra), RET 0x1c
**Purpose (confirmed):** queues the rows of a shadow image into the mask queue (display +0x674, 800 bytes = 50 spans of 16 bytes per screen row). An item (8 bytes): u16 page of the shade table (the rest of the first dword is ignored), u16 unused, u16 x offset from the end of the previous item, u16 length. Each span is stored as: +4 the `extra` of AddSprite (two u16: the lowest and the highest depth of the spans it darkens; 0 = those behind it), +8 x0, +0xa x1, +0xc depth, +0xe page.
**Behaviour:** the same cutting rules as the literal rows (004105a0), except that +4 is never a pixel pointer, so cutting never moves it. Clipping (only when the clip flag is set): an item that ends before 0 is skipped, one that starts before 0 starts at 0, one that starts after 639 ends the row, one that ends after 639 ends at 639.
**Port (5 Nov 2026, `codex/object-kinds`):** `RenderQueue::queueMaskRows` and `RenderQueue::Row::insert` in mask mode (core/renderqueue.cpp); `addSprite` sends every type other than 1 and 3 here, as the original. **Validation:** `re/tools/run_startup_check.sh` (gen_vectors_shadow.py + drivers/shadow_driver.cpp): the ORIGINAL AddSprite on random shadow sprites (random pages, depth windows, positions off the edges, many overlaps, up to 5 shadows per frame), then every mask row dumped (x0, x1, depth, extra, page of every span in list order) against the port's: 298,080 rows identical. Mutations of the port (the page read, the page stored, the pixel advance in cutting) caught. Not covered: a full mask row (the original overflows into the next row's memory; the port warns).
**Open questions:** none.
