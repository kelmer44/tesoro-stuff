# 00412120 — inferred_Display_RasterRow (scaled image setup)
Status: emu-compared (literal images) · Cluster: 32 · Convention: thiscall(Display *this, int x, int y, ushort depth, Image *image, int scaleX, int scaleY, int shear, int extra) — RET 0x20

**Purpose (confirmed):** Draws one deferred scaled image (called from Compose). Right edge = ((width−1)·scaleX >> 16) + x, bottom = ((height−1)·scaleY >> 16) + y. A bottom above y (negative scaleY) turns the image upside down: scaleY becomes −(0xffffffff / −scaleY), the walk starts from the last image row, and y moves to the bottom. Otherwise scaleY := 0xffffffff / scaleY (the source step per row, 16.16). The shear becomes (shear << 16) / rows (a zero row count faults). The first row is clipped at 0 (the source row accumulator and x advance for the rows cut), the last at 479 (signed compare). Nothing is drawn unless the x range overlaps 0..639, y < 480 and the bottom ≥ 0. By image type: 1 → 004108a0, 3 → 00410fb0, other → 00411580 with the extra value; the clip flag is "left edge < 0 or right edge > 639".
**Known flaw:** the raster functions add the 16.16 shear slope to a whole pixel x after every row, so any nonzero shear throws the image off the screen; the game passes 0 (the cursor does).
**Also:** scaled upside-down images start at a source row that can lie below the image unless the scale is a whole factor (rows·step rounds up); the game uses ±1.
**Port:** RenderQueue::rasterImage; images of types 3 and mask warn; a nonzero shear warns and is ignored.
**Validation:** see 00412e10.
