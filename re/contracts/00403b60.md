# 00403b60 — inferred_CdAudio_Init
Status: understood · Cluster: 8 · Depth: 0 · Convention: thiscall(CdAudio *this (0x1c0 bytes), HWND hwnd), RET 4

**Purpose (confirmed):** opens the CD-audio MCI device, counts the tracks and records each track's length in seconds.
**State written:** +0x24 hwnd; +0x1bc track count (-1 = unusable); MCI parameter blocks overlaid on the object: open block at +0x10 (+0x14 device id, +0x18 device type 0x204 = CD audio), status block at +0 (+4 result, +8 item, +0xc track); +0x2c + 4·(n−1) = length of track n in seconds.
**Behaviour:** +0x1bc = -1. `mciSendString("close all")`; if it fails, returns with nothing else done (no box). Open (MCI 0x803, flags 0x3000) device type 0x204; on failure device id = -1, box "Error al inicializar el CD", return (count stays -1). Status item 3 (number of tracks, wait) into +4; on failure box "Error al leer el CD", closes the device (0x804) if one is open, +0x28 = 0, return (count stays -1). Count = result, clamped to 100. Then for each track n = 1..count: status item 1 (length, with track number, wait) and length[n] = byte(+5) + byte(+4)·60 (minutes and seconds of the default MSF format). A zero-track disc gives count 0, which counts as usable.
**Used by:** DirectSoundInit 00403e00; a count below 0 makes the sound device "not ready" and the game refuses to start, so the original needs a readable audio CD (see open questions for the ScummVM side).
**Port:** CdAudio (core/sounddevice.cpp) over ScummVM's audio CD manager; the track count/length queries are not reproduced.
**Validation:** `re/tools/check_sound_init.py`: original code in Unicorn with a fake MCI: command order and flags, fields, 0/1/5/20/100/101/150 tracks with random lengths (clamp at 100), the three failure paths (box text, device closed or not). Not covered: real MCI.
**Open questions:** how a ripped-files setup should answer "number of tracks" (the engine does not use the count today).
