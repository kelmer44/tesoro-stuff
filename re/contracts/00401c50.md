# 00401c50 — inferred_Obj_UpdateBounds
Status: emu-compared · Cluster: 1 · Convention: fastcall(Obj *this)

**Purpose (confirmed):** Ticks the object's animation and recomputes its hit rectangle and the area it moved through.
**Outputs / state written:** +0x30 (u16) := current player's sequence; +0x20/+0x24 := (x + movementX, y + movementY) before the tick; calls vtable slot 2 (the object's animation tick, 00401c30 for the base class); +0x28/+0x2c := (x + movementX, y + movementY) after the tick, or (previousX + movementX, previousY + movementY) if the object moved (previous != current); hit rectangle of the sequence now shown, with i16 fields at sequence +0xc (x), +0xe (y), +0x10 (width), +0x12 (height): +0x10 := x, +0x14 := y, +0x18 := x + width, +0x1c := y - height.
**Calls:** virtual slot 2 (vtable 00428000: 00401c30; other classes 0040e6a0, 00407770).
**Edge cases:** reads the movement offset left by the previous tick before ticking; an object with no player crashes.
**Evidence:** asm 00401c50-00401d14; the hit rectangle also fixes the meaning of the sequence fields +0xc..+0x12.
**Port:** Object::updateBounds + virtual Object::updateAnimation. Deviation: returns without effect when the object has no player.
**Validation:** Differential check `re/tools/run_startup_check.sh` (gen_vectors_anim.py + drivers/anim_driver.cpp): the original function run in Unicorn (pool allocations replaced; name hash, Copy64Bytes, AnimTick and the vtable at 00428000 run as in the executable) vs engine Object. Constructor 211/211 (1-3 banks, 0-3 bank indices read through the record's pointer plus an offset, state sizes 0/6/100, random positions, sort values and names), plain constructor 211/211, setActive 141/141, setVisible 144/144, updateBounds 376/376 (bounds, moved area, shown sequence, then the object and all its players) including objects with the animation flag cleared and moved objects. Seven deliberate mutations of the port were caught. Not covered: bank counts of 0 for updateBounds (the original reads an unset player), the unmodelled fields (+0x3c room pointer, +0x5d byte, +0x60 state blob contents), movement read before the first advance (uninitialised in the original).
**Open questions:** what +0x30 is used for; what the moved area is used for (probably redraw or collision regions).
