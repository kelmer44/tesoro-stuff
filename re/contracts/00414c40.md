# 00414c40 — Exit_Activate: going through an exit (slot 20 of the plain exit)
Status: emu-compared · Convention: thiscall/fastcall (this = the exit)
**Behaviour:** Does nothing (returns 0) unless the verb is 0 and Jim's phase byte is 0. Looks up the destination object in the destination level; Jim faces the exit's own facing; the render queue is reset, the cameras of Jim's level are brought up to date, the frame is composed, the screens cleared, a fade (effect 4, speed 100) and a wait of 300 ms; Jim faces the arrival facing, is put into the destination level at the destination object's approach point, updated; the hover text is cleared; the destination object's exit-arrival slot runs. Returns 3.
**Port:** `ExitDoor::activate` (core/exitdoor.cpp), with `ExitHost`.
**Validation:** `gen_vectors_exits.py` + `drivers/exits_driver.cpp`: 1,300 sessions over all 10 subtypes and the plain exit (the original constructor with the factory's state size and vtable, then verb 0, verb 4, the right click, the arrival and the exit's arrival slot through the object's own vtable), 58,649 calls, 31,640 results, and every field of the exit, Jim's bytes and position and the 8 fake objects identical. 36 mutations of the port, all caught except three equivalent ones (the order of a state write against a script start that does not read it, and a threshold that only differs where it writes the same value).
