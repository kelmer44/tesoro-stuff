**Behaviour:** the interactive base (0x40ed10) on data+4, vtable 0042bb48 (a subtype overrides it afterwards), +0xd0 := u16 data[0] (text colour), +0xd2 := u16 data[1] (text width), +0xac := 0, +0xc0 := 0; then for every animation bank of the object (in order): the first three bytes of the bank's first header word (+0x32 of the player: they are the file's own tag, not a name given by the level) decide. "MIR" sets +0xac := its index (the bank used for facing frames, see 0x4103d0); "HAB" is appended to the pose table (+0xb0 + 4 * n, n counted in +0xc0): the speaking poses a script's say command chooses by its third number. Then +0xd4 := 0, +0xd5 := 0 and the visible bit is set (a subtype 3 object sets it once more in the factory). The record's kind data is 4 bytes of colour and width followed by the interactive data, so everything the base reads moves 4 bytes on (the base's byte 1 is the subtype, read by the factory, 0x409e50).
**Port:** `Character::init` (core/character.cpp), on top of `InteractiveObject::init` (new `dataStart` argument). `Character` owns a `Speaker` (its host answers come from the character's own parts and a `CharacterHost`).
