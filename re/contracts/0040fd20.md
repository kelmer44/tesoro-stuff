# 0040fd20 — inferred_ObjectList_PassB
Status: emu-compared · Cluster: 29 · Convention: fastcall(ObjectList **this) · returns 1, 2 or 3

**Purpose (confirmed):** One pass over the main object list: calls vtable slot 5 (offset 0x14, `update2` in the port) once on every active object. Pass A is slot 4, pass B is slot 5 (the base class stubs return 0).
**Behaviour:** first walk: clears the done flag (bit 9, 0x200) of every object. Then walks from the start: an object that is not active (bit 1) or is already done is skipped; otherwise the done flag is set, the cursor node is remembered, and the slot is called. A result of 2 or 3 ends the pass and is returned. Any other result: if the list cursor is still on the remembered node the walk goes on to the next element; if it moved (the call inserted or removed objects, which rewind and walk the list) the walk starts over from the beginning, and the done flags keep objects from running twice. Returns 1 when the walk reaches the end.
**Consequence:** an object inserted directly behind the cursor leaves the cursor on the same node, so it does not restart the walk and the new object is skipped until the next pass.
**Caller:** 00414420 RunFrame (A first; B only when A did not return 3).
**Port:** runUpdatePass / runUpdate2Pass (core/object.cpp), Object::update / update2 (default 0), flag Object::kPassDone. To compare the "cursor is still on the same node" test the port gives every CursorList node an id (reused last in, first out, like the original's free list; CursorList::cursorId). **Validation:** Differential check `re/tools/run_startup_check.sh` (gen_vectors_pass.py + drivers/pass_driver.cpp): the original PassA/PassB run in Unicorn on a real object list with 7 fake objects (random flags; vtable slots 4 and 5 point at machine-code stubs that call the original InsertByPriority and RemoveByObject on the list being walked and return 0-3), 500 cases with 1-3 passes each; compared return value, the order the objects were called in, the final list and every object's flags: 3530/3530. Mutations caught: never restarting after the list changes (2735/3530), not clearing the done flags first (2172/3530), not skipping inactive objects (1001/3530). Not covered: nodes shared between lists, pool overflow, real object kinds (the callees are stubs).
**Open questions:** what 2 and 3 mean to the callers beyond "3 skips pass B" (2 is returned by dialogue/script objects).
