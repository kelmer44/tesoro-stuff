# 00409c10 — inferred_Polygon_ClipToRect (Outline::clipColumns)
Status: emu-compared · Cluster: 12 · Convention: cdecl(Outline *src, int bx1, int by1, int bx2, int by2, Outline *out, int cx1, int cy1, int cx2) (y arguments unused)

**Purpose (confirmed):** cuts an outline to the columns cx1..cx2 into `out` (whose points buffer is preset by the caller; the routine writes count, split and the points).
**Behaviour:** (bx1, bx2) are the columns the outline covers (the hit rectangle). If bx1 < cx1 the first chain is skipped to the segment that crosses cx1 and a point (cx1, interpolated y) is emitted first; the source point at the segment start is then copied as well (the port keeps this). If cx2 < bx2 the first chain is copied up to the segment crossing cx2, then (cx2, y) and the cut point on the descending chain are emitted, split = index of the last point of the first chain; otherwise the rest of the first chain is copied and split = count − 1. The second chain is then copied the same way for the left edge (if cx1 <= bx1 it is copied whole). Interpolation: `(x − xi)·(yj − yi)/(xj − xi)` truncating, added to yi in 16 bits. A vertical segment at a cut divides by zero (the original faults; not reached by real data as far as known).
**Caller:** 00408c50, once per step of the movement.
**Port:** `Outline::clipColumns`. **Validation:** as 00409560, 1,732 random cases: count, split and every point identical.
**Open questions:** the copied pre-cut source point looks like an original quirk; it is reproduced because the original does it.
