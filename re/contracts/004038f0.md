# 004038f0 — inferred_Keyboard_Update (vtable 00428070 slot 0)
Status: emu-compared · Cluster: 7 · Depth: 1 · Convention: fastcall(Keyboard *this) · returns bool in AL

**Purpose (confirmed):** reads the keyboard once per frame (called by RunFrame 00414420) and updates the five key states.
**Behaviour:** GetDeviceState(256, buf); when it fails: Acquire, then GetDeviceState again; if that fails too, returns 0 and leaves the states untouched. Otherwise raw[i] = (buf[key[i]] >> 5) & 4 for the 5 table entries (DIK bit 7 → raw 4 = down), runs 00403700 with the count at +0x30, returns 1. Key states are read by the game from the byte array at +0x1c (index 0 Escape … 4 L); other callers read the second device (+0x34 of 00442074 is the key-state pointer: 004101f0 tests Escape through it).
**Port:** `Keyboard::setDown` (host events) + `Keyboard::update` (`InputStates::update`).
**Validation:** `re/tools/check_devices.py`: 300 random scans against the original state machine, plus the acquire-retry and double-failure paths (COM call order).
