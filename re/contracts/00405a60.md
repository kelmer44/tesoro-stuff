# 00405a60 — inferred_Script_Execute
Status: emu-compared · Cluster: 10 · Convention: fastcall(ScriptBlock *this) returns 2 (waiting) or 3 (finished this frame)

**Purpose (confirmed):** The script interpreter: runs entries from the program counter (+0xcc) until one has to wait. State: acting object (+0xac), per-character object cache (+0xb0), program counter, menu return position (+0xa0, -1 for none), variables (+0xd0, a byte array shared by the whole game), sleep start (+0xa8), level (+0x40). Entry layout: see STRUCTS.md. An op above 0xf loops forever on the same entry (the jump goes back to the start).
- 0 and 10: end the script: take it out of the main object list (0x40fb20), tell the **main cursor** (global 00442128, vtable slot 8) 1 (it was off while the script ran), release every cached character object whose busy byte (+0xc) is set (clear it, 0x401dc0, then 0x401a70 on its +0x38), return 3.
- 1 say: clears the speech timer (global 004420c8). Character index in [+8] (0 = Jim, global 004420fc): lazily resolve the object (0x408780 with the block's character key), make it the acting object, start the phrase [+4] on it (0x410330 with the voice number u16 at object+0xd0 and [+0xc]; Jim: 0x407ce0); return 3 (the pc stays on the line; the tick moves on).
- 2 sleep: remember the time (clock 0x413a10), return 2.
- 3 break: with no menu on screen (+0xa0 < 0), end like 0; else jump back to the menu start.
- 4 jmp: pc := [+4]. 7 if: variable[ [+8] ] == [+9] → pc := [+4], else next. 0xb set: variable[ [+4] ] := [+5].
- 5 menu: menu start := pc, pc++, flag 4420c0 := 0, then follow the chain of items: an item is listed when its variable byte (+6) is 0xff, or (+7 = 0) the variable is 1, or (+7 != 0) the variable is 0; the listed item's phrase is the word at +4 of the entry after it and its resume position is pc + 2. Next item = the u16 at +4 of the item (0xffff or 0 ends). At the end the acting object is Jim and the executor returns 3 so the tick shows the list. The lists are two fixed global arrays (phrases at 00442090, resume positions at 004420d0, 10 slots, count 00442088) shared by every script.
- 6 menu item reached by running into it: skipped (pc + 1).
- 8 run: with a block (resolved by 0x405630) start it with the same variables and level (0x405fd0) and return 3; without (the FANMTRONO special) label "ir" (name key of the string at 0042d204) selects 0x419f10(this, 0), any other label 0x419f10(this, 1) (the throne scene), then next.
- 9 sendmessage: the object is looked up by name key [+4] in the level [+0xc] (0 = the script's level) with 0x408780 and becomes the acting object. Orders: 0 animation (0x401de0 with first frame, last frame, third = last frame when the mode is stop else -1, loop = mode 2; mode 3 (wait) returns 3 without moving on), 1 walk (object slot 0x80 with x, y, this script as notification target; return 3, the pc stays: 0x406140 moves on), 2 look (slot 0x74), 3 activate (slot 8), 4 show (0x401d80); an unknown order only moves on.
- 0xc DO: calls the block's vtable slot 0x70 with the ordinal, then moves on from the pc as the routine left it. 0xd play video: 0x4132b0(display, [+4]) (the number IS passed); 0xe play sound: builds "<name at +4>.WAV", looks it up in the archive (0x403500) and plays it (0x404110); 0xf play track: 0x403cb0(sound device +0x1c, track, 1).
**Port:** `ScriptRunner::execute` (core/scriptrunner.cpp). Everything outside the script goes through `ScriptHost`. Compared with the original over 977 sessions (see gen_vectors_run.py); the original's calls are hooks that log, so what is compared is the order and arguments of the calls, the return values and the variables. **Open questions:** what the callees do (0x408780, 0x410330, 0x407ce0, 0x401de0, 0x4132b0, 0x404110, 0x403cb0, 0x419f10, 0x407d00 are not read yet); menus longer than 10 items overflow into neighbouring globals in the original (the port stops with an error); a script that runs off the end of its commands (only possible when two scripts share a menu) reads memory past the array in the original.
