# 004031a0 — inferred_Cursor_SetActive
Status: emu-compared · Cluster: 5 · Convention: thiscall(Cursor *this, byte active) — RET 4 · vtable slot 8

**Purpose (confirmed):** Sets the active flag as the base does (00401d60). When switching off: calls slot 18 (clear hover text) on every object of the hovered list (+0x6c), empties that list and ends the label (+0x78 := 0).

**Port:** Cursor::setActive, Object::setActive made virtual. **Validation:** Differential check `re/tools/run_startup_check.sh` (gen_vectors_cursor.py + drivers/cursor_driver.cpp): the original Cursor_Ctor (with the base constructors it calls), ProcessCandidates and SetActive run in Unicorn on a fake mouse (button byte) and 6 fake candidate objects whose vtable slots 14-18 are machine-code stubs returning scripted values (0-3, accept 0/1/5), objects sharing name keys, lists built by the original list code, 400 cases of 1-3 frames each with random hovered, previous-frame and touched lists and buttons none/left/right/both: constructor 400/400 (flags 0xe, sort value 0, empty label), candidate processing and SetActive 1187/1187 (return value, the order and arguments of every slot call, and the three lists afterwards). Mutations caught: hovered list copied in order instead of behind the first, result 3 not returned early, buttons swapped, previous entry not removed, stepping on after a non-zero result, hovered list not cleared or label not emptied by SetActive, SetActive reversed. One survives: pushing a candidate before or after showing its label (the stub methods never edit the cursor's lists). Not covered: slot methods that edit the lists, the main cursor's own constructor (00402300), the companion's verb (see open questions).
