# 004104a0 — inferred_Room_InsertSorted
Status: emu-compared · Cluster: 30 · Convention: thiscall(Room *this, Obj *object) — RET 4

**Purpose (confirmed):** Adds an object to the room's list ordered by x position (+0x4c), largest x first: it goes in front of the first listed object whose x is smaller (signed compare), so objects with equal x keep insertion order; otherwise it goes last.
**Outputs / state written:** rewinds the list, steps until an element with x < the new object's x, then inserts a node (value = object) at the cursor. The cursor is left on the node before the new one; the value slot holds the last element read. No capacity check, no duplicate check.
**Callers:** 00401bf0 Object_AttachToLevel (when flag 0x100 is set), 00407b80 Jim_EnterLevel, 004150d0, 0040ebd0, 00415290, 00402440, 004157b0 (attach slots of several kinds, to read).
**Port:** Room::insertSorted. **Validation:** Differential check `re/tools/run_startup_check.sh` (gen_vectors_room.py + drivers/room_driver.cpp): original Room_Ctor/InsertSorted/RemoveObject run in Unicorn (pool allocator replaced by a zeroing bump allocator) on 600 random cases (capacity 1-12, 12 fake objects with random x including negative, equal and extreme values, repeated inserts of the same object, removes of absent objects), each op followed by a dump of the chain and the value slot: Room state 9942/9942. A mutation of the comparison (< to <=) was caught (8222/9942). Not covered: node pool overflow (inserting more than capacity + 1), the node free-list order beyond what the chain shows.
**Open questions:** why descending x (probably draw/hit order for the room); the other callers.
