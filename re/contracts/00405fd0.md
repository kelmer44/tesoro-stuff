# 00405fd0 — inferred_Script_Start
Status: emu-compared · Cluster: 10 · Convention: thiscall(ScriptBlock *this, uint32 labelLo, uint32 labelHi, byte *variables, Level *level) — RET 10

**Purpose (confirmed):** Starts a script block at a label. Resolves every character name of the header to an object of `level` (0x408780) into the cache (+0xb0; entries are overwritten, not cleared first), sets the menu positions (+0xa0/+0xa4) to -1, looks the label up (+0xc4 table, 12 bytes each; position 0 if missing) into the program counter (+0xcc), keeps the level (+0x40) and the variable array (+0xd0), clears +0x8c, inserts the block into the main object list with priority 0x1e (0x40fa10), tells the main cursor (slot 8) 0 (off) and runs the first step (0x405a60). Returns 3.
**Callers:** 0x405a60 (`run`), 0x417b40 (menu clicks), 0x414560.
**Port:** `ScriptRunner::start`. Emu-compared. A missing label starts at entry 0 (as the three shipped dangling jumps do).
**Port (5 Nov 2026):** `ScriptHost::insertScript` must insert in *front* of equal priorities (`InsertByPriorityFront`, 0040fa10) as the original does. The port used the plain insert, so a script that runs a nested one (the recruiter's conversation) ran before it, reached its `return` at once and switched the pointer back on while the child's menu was showing: Jim could walk and the inventory opened during conversations. Not compared with the original (no driver checks the list order of scripts).
