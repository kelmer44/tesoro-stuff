# 004029f0 — inferred_Cursor_Update
Status: understood · Cluster: 6 · Convention: fastcall(Cursor *this) · returns int · vtable slot 4

**Purpose (inferred from the reading, not yet tested):** Per-frame pointer movement and the interface strip: positions the cursor and its companion at the mouse, and handles the key that opens or closes the interface and the strip scrolling.
**Behaviour (read, all branches):** returns 0 at once without a companion (+0x74). cx = camera x of the interface level (004421ec +0x80, +0x2c).
- 0 <= cx < 0x280: if the keyboard's first state byte has bit 3 (the key went down this frame): keyboard.slot 0 (acknowledge); if Jim's level is PRINCIPAL.LVL (the main menu): display effect (4, 100), main list emptied (ObjectList_Clear 0040fe20) and the update returns 3; if it is NUEVO.LVL (the new-game menu): Jim_EnterLevel(Jim, PRINCIPAL.LVL, its +0x70, 0, 0), display effect (4, 100), return 1; otherwise the thumbnail capture (004026d0) runs. Without the key: if the mouse button byte +1 has bit 3 or 4 (0x18), PageInterfaceRight (004025b0, see below) runs.
- cx == 0x280: with the key down: acknowledge, FindByKey(interface objects, NameHash64(string at 0042d060)) (result unused), camera x += 0x285, display effect (4, 100).
- cx > 0x280: with the key down: acknowledge, the same unused lookup, camera x -= 0x280, the interface object 004421fc and its child (+0xa8) and every object of its list (+0xa0) move by -0x280 in x, the held item (cursor +0x12c) gets flag bit 2 (visible), then the thumbnail capture. Without the key (or after that), if the mouse button byte +1 has bit 3 or 4: the same -0x280 paging, without the thumbnail.
- In every case except the early returns: the cursor is placed (Obj_SetPosition 00401d30, with the notify flag) at (mouse x + interface camera x, interface camera y - mouse y); the companion gets Jim's level as its level (+0x40), the position (mouse x + the camera x of Jim's level, camera y - mouse y), the level's +0x70 pointer at +0x3c, and is placed the same way. Returns 1.

**Corrections (5 Nov 2026):** the key is **Escape**: the keyboard device watches five keys in this order (scan codes 0x01, 0x1c, 0x39, 0x1f, 0x26 at 0042d078: Escape, Return, Space, S, L) and state byte 0 is Escape's. The three camera ranges are the interface's pages: 0..0x27f the strip at the bottom of the screen, exactly 0x280 and anything below 0 the scrolled-out screens (the save screen is at -0x285), beyond 0x280 a page that Escape and the right button turn back. The right button (button byte bit 3 or 4) pages the strip out when the first page is showing. "Acknowledge" is the keyboard's own update called again, which turns the press into a hold. The lookups by name (PRINCIPAL, IOBJETOS) have no use.
