# 00409560 — inferred_Polygon_ContainsPoint (Outline::contains)
Status: emu-compared · Cluster: 12 · Convention: cdecl(Outline *o, int x, int y) · returns bool (AL)

**Purpose (confirmed):** whether a point is inside an outline or on its border. An outline is {u16 count, u16 split, pointer to points}; a point is two s16 (x, y); the ring is closed by its last point (count − 1 edges are walked, so the last point should repeat the first).
**Behaviour:** even-odd crossing count to the right of the point, with exact-hit tests: a point on a vertex, on a horizontal edge or on an edge's interpolated x (`(y−y1)·(x2−x1)/(y2−y1) + x1`, truncating) returns true at once. A crossing exactly at an edge's start vertex counts only when the previous edge continues in the same vertical direction (previous points level with the vertex are skipped, wrapping to point count − 2). Edges are skipped at their end vertex. A count of 0 or 1 points returns false.
**Caller:** 00408c50 (ResolveOverlap) when one object has a single outline point.
**Port:** `Outline::contains` (core/outline.cpp). **Validation:** `re/tools/gen_vectors_outline.py` + `drivers/outline_driver.cpp`: 3,000 random closed convex outlines (on vertices, on edges, around), result identical; cases where the original read outside the data were dropped. Mutations: the previous-vertex test flip is equivalent (never equal), others caught in the overlap and clip routines.
