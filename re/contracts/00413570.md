# 00413570 — inferred_SpeechTable_Load
Status: emu-compared · Cluster: 33 · Convention: thiscall(SpeechTable *this, uint32 fileOffset) — RET 4

**Purpose (confirmed):** Reads one speech text file (`ID, "text"` lines) into a table object (8 bytes: entries pointer +0, count +4). The four files OBJETOS.TXT, ANIMS.TXT, CONVERS.TXT, ICONS.TXT are loaded by 0x413e60 in that order into the objects of global 00442110 (names 15 bytes apart from 0x42d990).
**Behaviour:** Seek to the offset, read the 4 byte size. Pass 1 counts the lines and the total text length: while the file position is not past the last eight bytes, read the ID (`" %[^,]s"`, white space skipped, up to a comma) and the text (`", \"%[^\"]s"`, up to the next quote), count, then skip two bytes (the closing quote and the next one, normally CR). Seek back, allocate 16 bytes per line and the text space, then read every line again: key = NameHash64(ID) (+0, +4), text copied straight into the text space (+0xc), voice = archive lookup of "<ID>.WAV" without error report (+8, 0 if missing). Finally the sort 0x4137c0.
**Entry (16 bytes):** key low, key high, WAV data offset or 0, pointer to the NUL ended text (bytes as in the file: an old DOS code page, e.g. 0xa8 for the opening question mark).
**Edge cases:** A line without a comma or without the quote leaves the ID or text as it was (the text then stays empty); the loop always advances two bytes, so a damaged line shifts the rest. IDs of 20 or more characters and texts of 1000 or more overflow the original's stack buffers (the port's buffers are as large as the file).
**Port:** engines/tesoro/core/speechtable.{h,cpp}::SpeechTable::load (text reader core/stdiotext.{h,cpp}, moved out of the script compiler).
**Validation:** Differential check `re/tools/run_startup_check.sh` (gen_vectors_speech.py + drivers/speech_driver.cpp): the original loader 0x413570 (with the sort 0x4137c0), the table lookup 0x4138b0 and the four-table search 0x413940 run in Unicorn on the shipped OBJETOS/ANIMS/CONVERS/ICONS.TXT, on 265 randomly edited slices of them (characters deleted, replaced, inserted; CRLF turned into LF) and on 7 crafted texts at the eight-byte end boundary. The CRT file calls are hooked onto an in-memory text, the archive lookup of ID.WAV (0x403500) is replaced by a name hash, the pool returns zeroed memory. Result 30 Oct 2026: 271/271 tables identical (8203 lines: key, wav offset, text, order after the sort, including equal keys), 8267/8267 lookups, 605/605 four-table searches (existing, missing, odd-case and empty names). Mutations caught: key order (low half first), sort direction, search direction, selection start, the two skipped bytes, the end boundary, the .WAV spelling, the table/line reference. Not covered: lines over 1000 characters and IDs of 20 or more characters (the original overflows its stack buffers there, so the vectors leave them out), the real archive lookup of ID.WAV, the original's behaviour on a table of a few bytes.
