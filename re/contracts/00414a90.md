# 00414a90 — Kind02 OnAttach (slot 0)
Status: emu-compared · fastcall(this). Allocates a list of capacity N (+0x72) at +0x74; for each stored key (+0x6c) finds the object of that name in the level (ObjectList_FindByKey on level +0x40's list) and appends it to the member list (List_InsertAfterCursor 00415200, at the end). A missing object appends null. (There is also a stack copy of seven words of the level's list header that is not used afterwards; the routine installs an exception frame.)
**Open questions:** whether a null member is later skipped (kind 11 walks the list and reads +0x5c of each).
**Port (31 Oct 2026, `codex/object-kinds`):** `ItemGroup::onAttach`.
**Validation:** Differential check `re/tools/run_startup_check.sh` (`gen_vectors_itemgroup.py` + `drivers/itemgroup_driver.cpp`, 31 Oct 2026): the original constructor (0x414930 with the animated base, the name hash 0x415c40 and the pool allocator replaced by a zeroing bump allocator) and OnAttach (0x414a90 with the list insert 0x415200 and, through an FS segment, its exception frame) run in Unicorn on 300 groups of 0, 1, 2, 3, 5, 9, 45 or 260 names (some missing from the fake level, some repeated) against a level of 0 to 8 named objects whose search (0x40f680) is replaced. The key list and the member list are read back by walking the original's list nodes; compared: the option byte (+0x70), the count (+0x72), every name key in order, and every member (which level object, or none) in order. 300/300 identical on each. 7 mutations of the port caught (name offset, name stride, option mask, count high byte, missing members skipped, name length, member order).
