# 004105a0 — inferred_Display_QueueRow_Literal (type 1 images)
Status: emu-compared · Cluster: 30 · Convention: fastcall-like, 6 stack args (rows, rowBlock, count, x, depth, clip)

**Purpose (confirmed):** Adds one image's rows to the span lists. For each image row, for each item: xs = (end of the previous item, starting at x) + xoffset, xe = xs + length − 1, pixels = item pointer. With the clip flag: an item entirely left of the screen (xe < 0) is dropped, one starting left of 0 is cut (pixels advance by 2 per cut pixel, xs := 0), one starting beyond column 639 ends the row, xe is capped at 639. Then the span is inserted into the row's list.
**Span insertion (node: next, pixels, x0 s16, x1 s16, depth u16; list ordered by x, disjoint):** walk the list; for a node with xs ≤ node.x1: if xe < node.x0 stop (insert before it). If the new depth is smaller (nearer): a node that starts before xs is cut at xs−1 (and split in two, the right part getting a copy of the node, if the new span lies strictly inside it); a node starting at or after xs is cut at its front (x0 := xe+1) and the walk stops, or is removed and returned to the free list if the new span covers it entirely. If the new depth is equal or larger (behind): the part of the new span before the node is inserted as its own span, and the new span continues after the node (xs := node.x1+1, pixels advanced); if the node covers the rest of the new span it is dropped. Pixel sources 0 and 1 (none / solid) are never advanced. At the end the remaining new span is inserted before the node where the walk stopped.
**Edge cases:** no check on the 125-node row pool (the original overwrites the next row; the port warns and drops).
**Port:** RenderQueue::queueLiteralRows + Row::insert.
**Validation:** Differential check `re/tools/run_startup_check.sh` (gen_vectors_render.py + drivers/render_driver.cpp): original reset + AddSprite run in Unicorn on 300 cases of synthetic literal images (1-8 rows, 0-4 items, built and loaded by the original loader) with 1-3 batches of 1-14 sprites at random positions including off every screen edge and clustered overlaps, depths 0-5, 65535 and random; after every batch the span lists of all non-empty rows (x0, x1, depth, which image and offset the pixels start at), the node bump counter and the free-list length: 574/574 dumps, 12437/12437 rows identical. 20 mutations of the port: 18 caught; the two cut cases for solid/none sources (pixels < 2) cannot occur with literal images, and `break` vs `continue` after a start beyond column 639 is equivalent. Not covered: solid/none spans, types 3 and mask, row pool overflow, scaled sprites.
