# 0040e5c0 — inferred_Obj_Kind03_Ctor (object kind 3, "sprite object")
Status: emu-compared · Cluster: 24 · Convention: thiscall(Obj *this, Record *rec, RoomRecord *room, AnimPlayer **bankTable, byte *data) — RET 0x10

**Purpose (confirmed):** Builds a kind 3 object: the animated base (00401aa0), vtable 0042b9c0, then starts one animation run chosen by the first two bytes of the kind's level data.
**Inputs:** `data` is the kind data buffer; the same pointer plus the record's data size (+0x1c) is where the bank indices begin, so data shorter than 2 bytes reads on into the bank indices. data[0] = first sequence, data[1] = mode.
**Outputs / state written:** base constructor first. Flags bit 2 (visible) := player 0's image count (+0x20) != 0. Then by mode (data[1]):
- 0: visible cleared, then as mode 1.
- 1: SetRange(first, first, loop 0, sum 0) on player 0; then the x and y words (+4, +6) of sequence record `first` are zeroed. The record array is shared by every object built from the same bank, so this clears that sequence's movement for all of them.
- 2: SetRange(first, -1, 0, 0): plays on until the next sequence without image.
- 3: SetRange(first, -1, 1, 0): same, looping.
- other: nothing more.
**Calls:** 00401aa0, 00401740 (AnimPlayer_SetRange).
**Yields / blocks / timing:** reads the clock through SetRange (start time = construction time).
**Edge cases:** no bounds check on `first` (the record write goes out of the array); an object with no banks reads an unset player pointer.
**Evidence:** asm 0040e5c0-0040e67c and jump table 0040e684 (modes 0-3); kind appears 217 times across the 50 shipped levels (counted with re/tools/drivers/level_kinds_driver.cpp).
**Port:** engines/tesoro/core/spriteobject.cpp::SpriteObject::init (Level::createObject, kind 3). Deviations: `first` outside the sequence table only warns; no banks only warns; the clock comes from the level load time.
**Validation:** Differential check `re/tools/run_startup_check.sh` (gen_vectors_sprite.py + drivers/sprite_driver.cpp): original constructor run in Unicorn on 600 synthetic animation files (1-3 players, modes 0-4 and 9, data sizes 0/1/2/3/6 including data that spills into the bank indices) vs engine: constructor 600/600 (flags, vtable, every player's flags/start/total/current/first/last/loop, and x/y of every sequence). 9 of 10 deliberate mutations caught; the survivor (unconditional tick) cannot differ while an object always has at least one bank. Not covered: modes where `first` is out of range, objects without banks, the shipped data.
**Open questions:** what kind 3 objects are in the game (217 of them: scenery, props, buttons?); meaning of data bytes after the first two (the shipped data sizes are not yet counted).
