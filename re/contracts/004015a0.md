# 004015a0 — inferred_AnimBank_LoadImage
Status: understood · Cluster: 1 · Depth: 8 · Convention: cdecl-like with RET 8: (FILE *f, int arena) returns image pointer or 0

**Purpose (confirmed):** Reads one image blob from the archive stream into pool memory and turns its stored offsets into pointers; converts colours to 5-5-5 when the display needs it.

**File format:** u32 size, then `size` bytes. Blob layout (offsets from blob start B): +0 u32 pixel data offset, +4 u32 pixel data byte size, +8 u16 (unknown), +0xa u16 N (number of span lists), +0xc u16 type, +0x10.. N entries of 8 bytes {u32 offset of an item array, u16 count (+4), u16 (+6) unknown}. Items are 8 bytes each.
**Outputs / state written:** allocates `size` bytes (align 4, arena) from the pool (global 00442100); returns 0 if the arena is full. Reads the blob. Then:
1. If the 5-5-5 flag (global 00442108 +0x67c) is set: for (size - pixelDataOffset) iterations, convert one 16-bit word at B + pixelDataOffset: w' = ((w >> 1) & 0x7fe0) | (w & 0x1f). The loop count is in words but equals the *byte* length of the pixel area, so it runs over twice the pixel data (see edge cases).
2. B+0 += B (offset to pointer); each of the N entry pointers (+0x10 + 8k) += B.
3. Per type: type 1: for every item in every entry (count from entry +4), the first dword of the item += B (pointer to pixels). Type 2: first dword := (dword & 0x1f) << 2 (a shadow intensity). Any other type with the 5-5-5 flag: first dword := the same 565→555 conversion of its low 16 bits, zero extended (solid colour); without the flag nothing.
Returns B.
**Calls:** fread 0041b4c0, Pool_AllocAligned 0040dc10.
**Yields / blocks / timing:** disk read.
**Edge cases:** step 1 converts `size - pixelOffset` words starting at the pixel data, i.e. up to that many bytes past the end of the blob (benign when the pool's free space follows, since later allocations overwrite it, but it would fault at the end of a pool and corrupts any later-initialised memory). The blob is trusted: no range checks on offsets or counts. Type values 3 (and 0, 4…) are all treated as "solid colour".
**Evidence:** asm 004015a0-00401731; the decompile matches. Callers 00401487 (AnimBank_Load, mode != 2) and 00401554 (deferred loader).
**Port:** engines/tesoro/core/animimage.cpp::AnimImage::load/parse. Deviations: pointer fields stay offsets from the start of the blob (the original adds the blob address); the 5-5-5 pass stops at the end of the blob; the blob is rejected when offsets or counts leave it.
**Validation:** Differential check `re/tools/run_startup_check.sh` (gen_vectors_anim.py + drivers/anim_driver.cpp): original Load/LoadImage/LoadDeferredImages/ScaleBrightness/SetRange run in Unicorn (fread/fgetpos/fseek/fsetpos, Archive_SeekEntry, the pool allocator and Clock_Now replaced by Python) on 700 synthetic animation files (0-9 sequences of types 0/1/2/4, 0-5 images of types 0/1/2/3/7, both pixel layouts, 5-5-5 and 5-6-5, load modes 0 and 2) vs engine AnimPlayer/AnimBank/AnimImage: load 700/700, header 700/700, flags 700/700, sequences 2509/2509, image positions 700/700, images after load 1396/1396, after deferred load 861/861, after brightness 832/832, SetRange 1748/1748. Five deliberate mutations of the port were all caught. Limits: synthetic data only (the shipped .DAT was not read); pool allocation/exhaustion is not modelled; the 5-5-5 overrun past the blob end and a sequence-less bank with images are not reproduced; pixel-first layouts are tested only without 5-5-5; item arrays shared by two spans are not tested; ranges reading past the sequence table are not tested.
**Open questions:** meaning of header +8 and entry +6; kind names for types 1-3 are only inferred from use (1 literal pixels, 2 shadow/intensity, other solid).
