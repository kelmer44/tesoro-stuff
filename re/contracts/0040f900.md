# 0040f900 — inferred_ObjectList_InsertByPriority
Status: emu-compared · Cluster: 28 · Convention: thiscall(ObjectList *this, value, int priority) — RET 8

**Purpose (confirmed):** Inserts an object so that the list stays in ascending priority order, after the objects of equal priority.
**Outputs / state written:** rewinds and walks; before the first element whose priority is greater than the new one (signed compare) it inserts a node (value, priority) in front of it; if there is none, walks again to the end and appends. The cursor is left on the node before the new element (the last node when appended).
**Edge cases:** no capacity check. 12 callers (objects entering a room list with their sort value as priority, to confirm).
**Port:** CursorList::insertByPriority. **Validation:** Differential check `re/tools/run_startup_check.sh` (gen_vectors_list.py + drivers/list_driver.cpp): the original list code run in Unicorn on real list memory (pool allocator replaced by a zeroing bump allocator) with 600 random operation sequences of 2-40 operations (capacity 1-14, repeated and unique values, negative priorities), each followed by a full dump of the chain and the cursor's data slots, vs engine CursorList: List state 5876/5876, List remove result 1448/1448, ObjectList state 6865/6865, RemoveByObject result 1867/1867, EndFrame result 966/966. The port was first a linked list in an array, then rewritten as a plain array with a cursor index; both versions pass every comparison. Four of five deliberate mutations of the first version were caught (one by hanging), and all five of the array version. Not covered: the cursor's start flag after Clear (every operation rewinds first, so nothing here can see it), stepping after Remove without a rewind (no such function exists; only inlined copies in other classes), node pool exhaustion, lists sharing one pool (Ctor with a source list), FindByKey (predicate search; not run in the emulator), the ObjectList cursor position (the generator only probes the List cursor, with the insert-after-cursor function).
**Open questions:** what the priority is at each call (probably the sort value +0x5e).
