# 00403e00 — inferred_Sound_Ctor (DirectSoundInit)
Status: understood · Cluster: 8 · Depth: 5 · Convention: thiscall(SoundDevice *this, HWND hwnd, GUID *guid), RET 8 (called by 00413b90 with guid 0)

**Purpose (confirmed):** builds the sound device: the CD-audio object, DirectSound, a 22 kHz 16-bit stereo primary buffer and three one-second secondary buffers.
**State written:** +0 primary buffer, +4 IDirectSound, +8/+0xc/+0x10 three 0x34-byte records (record +0 = secondary buffer or 0, record +0x2c = 0, the rest not cleared), +0x14 = 0 (last id), +0x18 = 0 (active count), +0x1c CD-audio object.
**Behaviour:** builds the CD object with 00403b60; if its count is negative: +4 = 0 and returns (nothing else, no box). DirectSoundCreate (ordinal 1 thunk 0041b3b0, guid, &+4); SetCooperativeLevel(hwnd, 2 = priority); CreateSoundBuffer with a primary description (size 0x24, flags 1) into +0; SetFormat on it: PCM, 2 channels, 22050 Hz, 88200 bytes/s, block 4, 16 bit. Then three times: new record, CreateSoundBuffer with flags 0x100c0 (pan + volume + get-current-position-2), 0x5622 = 22050 bytes (one second), format PCM mono 22050 Hz 8 bit (block 1); a failure leaves the record's +0 = 0 and the loop goes on. Failure boxes (Spanish "DIRECTSOUND: …": crear el objeto / nivel de cooperación / crear el buffer principal / definiendo el formato del buffer principal): +4 = 0 after the first two, +0 = 0 after the last two; the secondary buffers are then not created. Errors never abort; the caller tests 004040b0.
**Port:** SoundDevice (core/sounddevice.cpp) on ScummVM's mixer; the buffer sizes and formats here are the original's, the port streams through the mixer instead of three 1-second ring buffers.
**Validation:** `re/tools/check_sound_init.py`: fake DirectSound; fields, description and format bytes of every buffer, all four failure paths, a failed secondary buffer (null record, still ready), unreadable CD (DirectSound never created). Not covered: real DirectSound.
**Open questions:** the three secondary buffers' use (voices and effects, 8-bit mono 22 kHz) is read in 00404110/004042c0, not here.
