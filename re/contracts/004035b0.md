# 004035b0 — inferred_InputDevice_Ctor (DirectInput device base)
Status: understood · Cluster: 7 · Depth: 1 · Convention: thiscall(Device *this, HWND hwnd, HINSTANCE hinst, DWORD coopFlags, const GUID *guid, const DIDATAFORMAT *format), callee pops 5 args (RET 0x14)

**Purpose (confirmed):** Common constructor of the keyboard and mouse: shares one DirectInput object between devices and creates, formats and configures this device.
**Inputs:** hwnd (owner of the message boxes and of the cooperative level), hinst (DirectInputCreateA), coopFlags, device GUID, data format. Keyboard passes (6, GUID_SysKeyboard, c_dfDIKeyboard), mouse (5, GUID_SysMouse, c_dfDIMouse); flags 6 = non-exclusive + foreground, 5 = exclusive + foreground.
**Outputs / state written:** vtable (this+0) = 0042806c (one slot, a CRT abort stub); device pointer (this+4); globals 00442078 (shared IDirectInput) and 0044207c (number of devices using it).
**Behaviour:** if the count is 0, DirectInputCreateA(hinst, 0x700, &shared, 0); on failure shows the error box "DIRECTINPUT: error al crear el objeto DirectInput", clears the shared pointer and returns early **without** counting this device and **without** writing +4. Otherwise count++, shared->CreateDevice(guid, &this+4, 0), device->SetDataFormat(format), device->SetCooperativeLevel(hwnd, coopFlags). Each failure shows its own box (error al inicializar el dispositivo / definiendo el formato / al definir el nivel de cooperación), sets +4 = 0 and returns. No retry, no abort: the game start-up then finds the device not ready (004036c0) and shows its own error.
**Calls:** DirectInputCreateA (0041a076, import thunk); IDirectInput slot 3 (CreateDevice); IDirectInputDevice slots 11 (SetDataFormat) and 13 (SetCooperativeLevel); MessageBoxA.
**Yields / blocks / timing:** none.
**Edge cases:** the early return on DirectInput failure leaves +4 as the allocator gave it (operator new zero-fills here, checked: the emulated allocator in the check does the same; the original's `_nh_malloc` is replaced and was not shown to zero). If it does not, IsReady could read garbage; reachable only when DirectInput fails.
**Evidence:** asm 004035b0–004036bb; GUIDs read from the executable: 6F1D2B61-… (keyboard), 6F1D2B60-… (mouse); formats: dwSize 0x18, objSize 0x10, flags 2, data size 0x100 / 0x10, object count 0x100 / 7.
**Port:** none (host input comes from ScummVM events). **Deviations:** the message boxes and DirectInput set-up have no equivalent.
**Validation:** `re/tools/check_devices.py`: original code in Unicorn with a fake DirectInput (vtables of stubs): call order and arguments of every COM call, globals, all four failure paths (message text, device left unready, count untouched when DirectInput itself fails). Not covered: real DirectInput behaviour.
**Open questions:** whether `_nh_malloc` zero-fills (only matters on the DirectInput failure path).
