# 00413b00 — inferred_RandomRange
Status: understood · Cluster: 34 · Depth: 0 · Convention: stdcall(int min, int max) returns int

**Purpose (confirmed unless marked inferred):** The game random-number function: a value in [min, max] derived from the low ten bits of GetTickCount(), not from a seeded generator.

**Inputs:** min, max (signed 32-bit). Reads GetTickCount().
**Outputs / state written:** Let t = GetTickCount(). f = bit-permutation of t bits {9,8,7,5,0,1,2,3,4} (see evidence) giving a 10-bit fraction 0..1023; result = ((f * (max - min + 1)) >> 10) + min using signed 32-bit arithmetic (arithmetic shift).
**Calls:** GetTickCount.
**Yields / blocks / timing:** Time dependent: two calls within the same millisecond return the same value; no state is kept between calls.
**Edge cases:** max < min yields a non-positive range factor (result below min); overflow wraps in 32 bits; the shift is arithmetic.
**Evidence:** Disassembly 00413b00-00413b84 (full listing read); 15+ callers. f = ((((((t&0x200)|((t>>2)&0x100))>>2|(t&0x100))>>2|(t&0x80))>>2|(t&0x20))>>1) | ((((((t&2)|((t&1)<<2))<<2|(t&4))<<2|(t&8))<<2|(t&0x10))<<1).
**Port:** engines/tesoro/core/random.{h,cpp}::randomRange (branch codex/fresh-core, uncommitted); the engine wrapper `TesoroEngine::randomBetween` passes `getMillis()`. Deviation: ScummVM's millisecond counter starts near zero at launch while GetTickCount counts from boot; the low bits used are equally uniform.
**Validation:** Differential check `re/tools/run_startup_check.sh`: vectors recorded from the original machine code in Unicorn (GetTickCount stubbed) vs the engine's C++ compiled by the driver `re/tools/drivers/startup_driver.cpp`. 29 Oct 2026 result: RandomRange 4000/4000, RandomRange7 4000/4000, nameKey64 522/522, clock `now` 4141/4141 over 300 random op sequences (ticks include gaps of 499/500/501 ms, 100 s jumps, backwards steps, suspend/resume). Does not cover real host time, the frame loop, or other states.
**Open questions:** Which bits of t actually vary between calls in practice (low bits change every ms; the permutation decides the visible randomness).
