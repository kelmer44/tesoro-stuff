# 0040e6b0 — inferred_Obj_Kind03_Draw (vtable 0042b9c0 slot 6)
Status: emu-compared · Cluster: 24 · Convention: thiscall(Obj *this, Camera *camera) — RET 4

**Purpose (confirmed):** Draws the object's current picture: slot 6 of the object vtable, called by UpdateRoomCameras (00408550) for every visible, active, unprocessed object of a room.
**Behaviour:** record = the sequence record the current player is on (player +0x30). If its image slot (+0x18) is 0, nothing happens. Otherwise calls the display's image blit (00411f80 on global 00442108) with
x = objX − camera.scaledX + player.moveX + 320 + record.imageX,
y = (camera.scaledY − objY) − record.imageY − player.moveY + 240,
depth = u16 at object +0x5e (sort value), the image blob, extra = 0.
So the screen is 640x480, the camera's scaled position is the world point at the centre, and world y points up.
**Calls:** 00411f80.
**Port:** SpriteObject::draw → Display::drawImage (core/display.h). The blit itself is not ported yet (00411f80 and its three blitters).
**Validation:** Differential check `re/tools/run_startup_check.sh` (gen_vectors_sprite.py): original draw run with the blit replaced by a recorder, 991/991 draws match (hidden/no-image decisions, x, y, depth, which image) over random camera positions, object positions (including 17-bit values) and sort values, after random ticks and movement. Not covered: draws before the player's movement is first written (the original reads uninitialised 0xcdcd there), garbage sequence index.
**Open questions:** the depth value's role in the blit (00411f80 passes it on); what `extra` is for the shadow blit (kind 0x0040e760 passes object +0x70).
