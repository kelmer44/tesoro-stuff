# 00403aa0 — inferred_Mouse_Update (vtable 00428074 slot 0)
Status: understood · Cluster: 7 · Depth: 1 · Convention: fastcall(Mouse *this) · returns bool in AL

**Purpose (confirmed):** reads the mouse once per frame (RunFrame 00414420), moves the pointer and updates the three button states.
**Behaviour:** GetDeviceState(16, buf) with one Acquire-and-retry; if both fail returns 0 and changes nothing. The buffer is a DIMOUSESTATE (lX, lY, lZ, four button bytes). Stores lX at +0x30 and lY at +0x34 (the raw movement of this frame; lZ is ignored), adds them to the position (+0x38, +0x3c), then clamps in this order: x below +0x20, y below +0x24, x above +0x28, y above +0x2c (signed). Buttons: raw[i] = (button[i] >> 5) & 4 for the 3 buttons (+0x18), then 00403700 turns raw into states at +0x1c. Returns 1.
**Button bytes:** index 0 left, 1 right, 2 middle. The "left button" tests in the cursor code read state byte 0 with mask 8 (pressed this frame); mask 0x10 on byte 0 means "pressed again within the release delay of the same button" (state 0x10), which ProcessCandidates 00402e80 treats as its right-click path. The real right button is byte 1 (masks 0x18 in 004029f0/004101f0).
**Port:** `Mouse::moveTo` + `Mouse::update` (host gives the position; the original adds movement, same clamped result when the host position is inside the limits). **Validation:** `re/tools/check_devices.py`: 300 random movements (including beyond both limits) and buttons against the original, position, raw movement, states and return value, plus the acquire-retry order. Mutations caught (clamp edge, button bit).
**Open questions:** the host gives absolute position; the original accumulates relative movement, so a host cursor that is warped or confined differently from DirectInput's exclusive mode may feel different (sensitivity is 1:1 in the original, no acceleration).
