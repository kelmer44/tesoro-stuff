# 00403cb0 — inferred_CdAudio_PlayTrack
Status: understood · Cluster: 8 · Convention: thiscall(CdAudio *this (the object at sound device +0x1c), byte track, byte flag) — RET 8
**Behaviour:** stops what plays (MCI command 0x808, if a device is open), clears +0x28; when track ≤ the number of tracks (+0x1bc) it sets time format "tracks" (0x80d with 0x400), and plays from `track` to track+1, or to the end when it is the last track (MCI play 0x806 with from/to); on success +0x29 := track and +0x28 := flag (the script passes 1; used as a "playing" flag for a later replay). A failed command closes the device (0x804). **Port:** `CdAudio` (core/sounddevice.cpp) over `ScummCdBackend` (ScummVM's audio CD manager, looping; the window's MM_MCINOTIFY handler 0x403dc0 restarts the track when it ends, which is what the loop stands for). Not compared (MCI). **Open:** the track numbers are the disc's own numbers (a data track may come first); how they map to ripped files is for the user's setup. Level music: 0x408840 plays the two track bytes of the level's kind 1 object (+0x7c, +0x7d); 0x416800 plays track 9 under conditions of Jim's option bytes.
