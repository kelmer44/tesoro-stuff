# 00410420 — inferred_Room_Ctor
Status: emu-compared · Cluster: 30 · Convention: thiscall(Room *this, List *level_list, RoomRecord *record, int index, short sort_offset) — RET 0x10

**Purpose (confirmed):** Fills one 0x10-byte room entry of the level and gives it an empty object list.
**Layout written:** +0 index (third argument), +4 dword from record +0x24 (the camera divisor: Level_UpdateRoomCameras passes it to Camera_UpdateToward, see 00401fc0), +8 short sort offset (fourth argument), +0xa short from record +0x22, +0xc pointer to a new plain List (header 0x1c, node block capacity*8+0x18, from arena 1) whose capacity is read from the first argument +0x10.
**Caller:** 004080e0 Level_Load, once per room (record read as 0x28 bytes from the level file; the running sort offset grows by the short at +0xa of each record, so +0xa is the room's draw-order extent).
**Calls:** Pool_AllocZero 0040db40.
**Port:** Room::init (core/room.h). The list is a fresh CursorList; capacity is not modelled. **Validation:** Differential check `re/tools/run_startup_check.sh` (gen_vectors_room.py + drivers/room_driver.cpp): original Room_Ctor/InsertSorted/RemoveObject run in Unicorn (pool allocator replaced by a zeroing bump allocator) on 600 random cases (capacity 1-12, 12 fake objects with random x including negative, equal and extreme values, repeated inserts of the same object, removes of absent objects), each op followed by a dump of the chain and the value slot: Room state 9942/9942. A mutation of the comparison (< to <=) was caught (8222/9942). Not covered: node pool overflow (inserting more than capacity + 1), the node free-list order beyond what the chain shows.
**Open questions:** whether the first argument is really the level's own list (only its capacity is used).
