# 00407580 / 00407510 — inferred_Jim_LoadState / SaveState (slots 9 / 10)
Status: ported (save compared with the original, load by reading). Save: position (8 bytes from +0x4c), facing (+0x10c, 4), the bank index (+0x32, 1 byte), +0x110 (4 bytes), flags (+0x68, 4) in that order. Load reads the same in the same order and first clears +0xd5 and takes Jim out of the main list. **Port:** `Jim::saveState` / `Jim::loadState` (core/jim.cpp). The four bytes at +0x110 are the game's progress: scene phase, story step, subtitles setting and one more byte; the port keeps them in `World` and writes and reads them through `JimWorld::progressBytes` / `setProgressBytes` (until 5 Nov the saved word was never filled in, so a loaded game lost the story step, the scene phase and the subtitles setting). The byte at +0x32 is the bank last chosen, not the bank that is playing: Jim's walk switches the playing bank only, so the byte can differ from it; the port now keeps both (`AnimSet::selectedBank`). **Validation (save only):** `gen_vectors_jim.py` op G, the original 0x407510 run in Unicorn with its writes recorded, vs `drivers/jim_driver.cpp`: the bytes written are identical in every session (one op per session on average, the four progress bytes random each time). The loader mirrors it by reading and is not compared. The file is still the port's own.
