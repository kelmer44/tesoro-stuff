# 004079e0 — inferred_Jim_Slot12 (collision callback)
Status: understood in outline · Cluster: 29 · Convention: thiscall(Jim *this, Object *other) → 1 — vtable slot 12 (hitter.onTouched(other, extra))
**Behaviour (read, not ported):** only while walking (+0xd5): the target position (+0x54/+0x58) := the current one, out of the main list. If the walk was not direct and `other` (the level's kind 1 object, whose +0x78 is the walk area) has a walk area: the route is recomputed with 0x414f10 (FindPath: vertex route); when it returns false (no vertices) Jim faces his facing and the target is told (its slot 13) and 1 is returned; if it returns true Jim has been sent to the first vertex (direct walks) and the target is told when he gets to the end. Otherwise (a direct walk) the direct flag is cleared and Jim faces (slot 29) his facing. Slot 11 of Jim (0x4079d0) is "state byte +0x5c == 7", which makes him the hitter of the collision test only in that state. **Port:** `JimWalker` (core/jimwalker.cpp): gen_vectors_jimwalk.py + drivers/jimwalk_driver.cpp, 1,000 random sessions, 39,146 operations, 52,981 calls identical (the callees are logging hooks; the animation is modelled as the current bank and which banks play); 28 mutations, 27 caught and one equivalent (dx = 0 cannot happen when |dy| < |dx|). Not covered: what the hooked calls do inside, Jim's constructor, his collision test slot 11. **Open:** which object collides with Jim here, and when his state byte is 7 (inferred: the kind 1 object as `other`).

**Update 31 Oct 2026:** from the shipped data, `other` (the touching object whose +0x78 is the route) is the kind 7 floor, which names the kind 8 route object; the kind 1 object's target is the same floor (used for the scale). `WalkFloor::path()` is that link.
