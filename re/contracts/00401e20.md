# 00401e20 — inferred_Obj_LoadState
Status: emu-compared · Cluster: 3 · Convention: thiscall(Obj *this, FILE *stream) — RET 4 · vtable slot 9

**Purpose (confirmed):** Reads the object's saved state from a stream with fread (0x41b4c0); the exact mirror of Obj_SaveState (00401ee0).
**Stream format (little endian, as the executable writes it):** if the object has the animation flag (bit 4): bank index (1 byte); then the current player's first sequence (2), last sequence (2), the LOW byte of the sequence being played (1) and the LOW byte of the play flags (1). Then, if the object has a state blob (+0x60 not null, i.e. it was built with a state size): the size (2, stored in +0x64) and that many blob bytes.
**Widths:** the player's current sequence (16 bits) and play flags (32 bits) are saved as one byte each; loading writes only that byte and keeps the others. Loading takes the bank index from the stream and makes that bank's player current (+0x38) without starting it.
Short reads leave the target bytes as they were (fread results are ignored).
**Callers:** none direct; slot 9 of the base vtable and of every kind. Level_LoadState 00408710 calls it per object (name key, then flags, then this); whether the stream is a save-game file or a level state kept in memory is not established.
**Port:** Object::loadState (virtual), AnimSet::loadState, AnimPlayer::loadState. The object now keeps its state blob (stateBlob(), sized by initAnimated). **Validation:** Differential check `re/tools/run_startup_check.sh` (gen_vectors_state.py + drivers/state_driver.cpp): the original Obj_SaveState and Obj_LoadState run in Unicorn (fread and fwrite replaced by a byte buffer) on a fake object with 1-3 players, state sizes 0/6/40, objects with and without the animation flag, random 32-bit flag words and 16-bit sequence numbers, random and truncated input streams; compared the bytes written and the object state (bank, every player's flags/first/last/current, size, blob): 2995/2995 states, 1001/1001 saved byte strings. The check found one bug in the first port (a short read of the bank byte reset the bank to 0 instead of leaving it). Mutations caught: flags written as 16 bits, flags read as 32 bits, current read as 16 bits, size not written, size not read, bank byte reset on a short read. Not covered: the high byte of the sequence number before a load (the harness can only prime it to 0..255), a saved bank outside the table, a saved size larger than the object's blob (the original overflows the buffer; the port grows it and warns).
**Open questions:** as for 00401ee0.
