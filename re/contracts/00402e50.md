# 00402e50 — inferred_Cursor_IsHitter (was Cursor_IsFlag10)
Status: emu-compared · Cluster: 5 · Convention: fastcall(Obj *this, Obj *other) — RET 4 · vtable slot 11

**Purpose (confirmed):** Collision protocol slot 11: returns bit 10 (0x400) of the object's flags, ignoring the argument. Level_CollisionPass asks A.slot11(B) then B.slot11(A) to decide which of two overlapping objects is the hitter. Nothing read so far sets bit 10; it is presumably set by Cursor_Update (not read).

**Port:** Cursor::isHitter, Object::isHitter (default false), flag Object::kHitter. **Validation:** Differential check `re/tools/run_startup_check.sh` (gen_vectors_cursor.py + drivers/cursor_driver.cpp): the original Cursor_Ctor (with the base constructors it calls), ProcessCandidates and SetActive run in Unicorn on a fake mouse (button byte) and 6 fake candidate objects whose vtable slots 14-18 are machine-code stubs returning scripted values (0-3, accept 0/1/5), objects sharing name keys, lists built by the original list code, 400 cases of 1-3 frames each with random hovered, previous-frame and touched lists and buttons none/left/right/both: constructor 400/400 (flags 0xe, sort value 0, empty label), candidate processing and SetActive 1187/1187 (return value, the order and arguments of every slot call, and the three lists afterwards). Mutations caught: hovered list copied in order instead of behind the first, result 3 not returned early, buttons swapped, previous entry not removed, stepping on after a non-zero result, hovered list not cleared or label not emptied by SetActive, SetActive reversed. One survives: pushing a candidate before or after showing its label (the stub methods never edit the cursor's lists). Not covered: slot methods that edit the lists, the main cursor's own constructor (00402300), the companion's verb (see open questions).

**Correction (30 October 2026):** the function reads the flag of its **stack argument**, the other object, not of the pointer (`MOV EAX,[ESP+4]; MOV EAX,[EAX+0x68]; SHR 10; AND 1; RET 4`). The decompiler dropped the `this` in ECX and showed the stack argument as `param_1`. So the pointer is a hitter for every object marked 0x400 (Jim, the clickable kinds with the shared base's 0x508, kind 9), which is how it touches menu items. The earlier port tested the pointer's own flag; that was wrong and the earlier cursor check did not exercise this method. Fixed: Cursor::isHitter tests `other->flags() & kHitter`. **Validation:** gen_vectors_hitter.py + drivers/hitter_driver.cpp: 2000 random flag pairs, 2000/2000 identical (987/2000 before the fix).
