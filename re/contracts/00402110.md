# 00402110 — inferred_Camera_Ctor
Status: emu-compared · Cluster: 4 · Convention: fastcall(Camera *this)

**Purpose (confirmed):** Clears the target (+0) and the glide duration (+0x10); nothing else is written (the level allocates the object zeroed).
**Layout (0x40 bytes, level +0x80, built zeroed by the level):** +0 target object (null for none); +4/+8 start x,y of a glide; +0xc glide start time; +0x10 glide duration (0 = none); +0x14/+0x18 goal x,y; +0x1c min x, +0x20 max y, +0x24 max x, +0x28 min y (bounds for the centre); +0x2c/+0x30 current centre x,y; +0x34/+0x38 centre scaled by 300 / divisor; +0x3c the divisor. Which of the two y bounds is the top of the screen is not established (Level_Load passes -320, 239, 319, -240).
**Caller:** 004080e0 Level_Load.

**Port:** Camera::init (zeroes everything). **Validation:** Differential check `re/tools/run_startup_check.sh` (gen_vectors_camera.py + drivers/camera_driver.cpp): the original camera functions run in Unicorn (game clock replaced by a settable time) on 600 random sequences of 3-40 operations (bounds, target on/off, target x including values at the dead-zone edges, direct positions, glides, updates with divisors 1, -7, 100-900, time steps including the exact end of a glide and 32-bit wraparound), after every operation compared the centre position and the scaled position, and the result of SetPositionClamped: 15001/15001 states, 1105/1105 clamp results. Mutations caught: scroll step 99, end of glide `<=`, dead-zone `<=`, goal-x not reset after a glide, right-edge test off by one, left-edge test `<=`, glide start time not stamped. One survives: not resetting the goal y after a glide finishes (needs a glide to an out-of-bounds y followed by a target scroll). Not covered: divisor 0 (crashes in the original; the port warns), the fields that are not observable through the position.
