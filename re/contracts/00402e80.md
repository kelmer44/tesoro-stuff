# 00402e80 — inferred_Cursor_ProcessCandidates
Status: emu-compared · Cluster: 5 · Convention: fastcall(Cursor *this) · returns int

**Purpose (confirmed):** Once per frame, turns the objects the pointer touched into hover labels and clicks.
**Behaviour:** (1) the shared "hovered last frame" list (00442060) is emptied and refilled from the cursor's hovered list (+0x6c) with an insert-behind-the-first-node quirk (first element stays first, the rest end up in reverse order); the hovered list is then emptied. (2) For each object of the touched list (+0x70), until a result other than 0 is set: if no object with the same 64-bit name key is in the shared list (a new one): when its slot 16 says yes, it is appended to the hovered list and slot 17 (show hover text) provides the result. If one is (it stays under the pointer): left button (mouse button byte bit 3) calls slot 14 with the verb, else right button (bit 4) calls slot 15 with the verb, else slot 17; a result of 3 is returned at once; otherwise the object is appended to the hovered list and removed (by pointer) from the shared list. (3) Every object still in the shared list gets slot 18 (clear hover text). Returns the last result. The verb is the current animation index of the cursor's own player (+0x38 +0x30). The touched list is not emptied here (Cursor_Update2 does it).
**Slots:** 14 SetVerbAndClick, 15 right click (forwards to 14 in the base), 16 accepts the pointer (base returns true), 17 show hover text (base returns 1, which ends the loop: only the first new object gets the label), 18 clear hover text.
**Caller:** 004030e0 Cursor_Update2.

**Port:** Cursor::processCandidates(buttons, verb): the verb is passed in; CursorList::insertBehindNext for the refill. **Validation:** Differential check `re/tools/run_startup_check.sh` (gen_vectors_cursor.py + drivers/cursor_driver.cpp): the original Cursor_Ctor (with the base constructors it calls), ProcessCandidates and SetActive run in Unicorn on a fake mouse (button byte) and 6 fake candidate objects whose vtable slots 14-18 are machine-code stubs returning scripted values (0-3, accept 0/1/5), objects sharing name keys, lists built by the original list code, 400 cases of 1-3 frames each with random hovered, previous-frame and touched lists and buttons none/left/right/both: constructor 400/400 (flags 0xe, sort value 0, empty label), candidate processing and SetActive 1187/1187 (return value, the order and arguments of every slot call, and the three lists afterwards). Mutations caught: hovered list copied in order instead of behind the first, result 3 not returned early, buttons swapped, previous entry not removed, stepping on after a non-zero result, hovered list not cleared or label not emptied by SetActive, SetActive reversed. One survives: pushing a candidate before or after showing its label (the stub methods never edit the cursor's lists). Not covered: slot methods that edit the lists, the main cursor's own constructor (00402300), the companion's verb (see open questions).
