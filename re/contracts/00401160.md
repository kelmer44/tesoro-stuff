# 00401160 — inferred_AnimBank_Load
Status: understood · Cluster: 1 · Depth: 9 · Convention: thiscall(AnimPlayer *this, uint32 entryOffset, int arena, int mode) — RET 0xc; 0x428 byte frame

**Purpose (confirmed):** Reads an animation bank (.ANM data) from the archive into an AnimPlayer: header, sequence records, and either every image (mode != 2) or only their file positions (mode 2, loaded later by LoadDeferredImages).

**Inputs:** entryOffset = result of Archive_FindEntry (callers 00413e60, 004070c0, 004080e0 all pass it); the function seeks to entryOffset + 4 (a second 4-byte skip; meaning unknown). arena = pool arena for tables; mode: 0 normal, 2 deferred (callers use 0 and 2; images then use arena = mode).
**File layout (read from entryOffset+4):**
- Header 0x18: +0 u16 sequence count, +4 u16 image count, +8/+0xc/+0x10 three dwords (copied raw), +0x14 u8 (== 1 sets flag bit 3), other bytes unused here.
- Sequence records, count times: 0x18 bytes {+0 d, +4 d, +8 u16, +0xa i16 imageIndex, +0xc d, +0x10 d, +0x14 u16 type, +0x16 u16 extraSize}, immediately followed by `extraSize` bytes of extra data.
- Images, imageCount times (see AnimBank_LoadImage).
**Outputs / state written (this):** +0x22 seqCount, +0x20 imageCount, +0x32/+0x36/+0x3a the three header dwords, +0x18 := (flagbyte == 1) << 3 (all other bits 0), +4 := alloc(imageCount*4), +0 := alloc(imageCount*4), +0x1c := alloc(seqCount*0x24) (all align 4, arena), +0x14 := mode.
Per sequence record i (memory record R, 0x24 bytes): R+0,+4 copied; R+8 u16 = file +8; R+0xa u16 = file type; R+0xc, R+0x10 copied; R+0x18 := pointer to slot images[imageIndex] (0 if imageIndex < 0); extra data by type:
- type 0, 1: R+0x1c := 0 (u16), R+0x14 := 0.
- type 2: R+0x14 := 0; count = extra u16 at +0, R+0x1c := count; R+0x20 := alloc(count*4); entries are dwords copied from extra+6+4k. (extra bytes +2..+5 not used).
- type 4: count = extra u16 +0; R+0x1c := count; R+0x20 := alloc(count*4) and R+0x14 := alloc(count*2); entry k reads three u16 at extra+8+6k: first two → R+0x20 (x at +4k, y at +4k+2), third → R+0x14 (+2k). (the older notes call these floor points: x, y, scale)
- other types: nothing from extra (R+0x1c, R+0x14, R+0x20 are left as allocated, uninitialised).
Then if R+0x1c != 0: R+0x1e := index of the first entry i < count-1 whose first u16 (signed compare) is greater than the next entry's first u16, else count-1 (0 when count == 1).
Images: for k in 0..imageCount-1: this+4[k] := fgetpos low dword (position of the size field); mode 2: read u32 size and seek forward by size (relative); else images[k] := AnimBank_LoadImage(file, arena = mode).
Finally the first record's u16 at +4 and +6 are subtracted from the same fields of every other record (records 1..n-1), and then record 0's +4 and +6 are set to 0 (positions become relative to the first record; both reads use sign-extended 16-bit values).
Returns this.
**Calls:** Archive_SeekEntry 004032e0, fread 0041b4c0, fgetpos 0041b490, fseek 0041b3f0 (whence 1), Pool_AllocAligned 0040dc10, AnimBank_LoadImage 004015a0.
**Yields / blocks / timing:** disk reads only.
**Edge cases:** alloc failures (0) are not checked except in LoadImage. Extra data larger than the 0x3e8-byte stack buffer would overflow the frame. seqCount == 0 makes the final normalisation read record 0 of an empty array. Sequence records whose type is not handled keep uninitialised +0x14/+0x1c/+0x20 (+0x1c is tested afterwards: it reads uninitialised pool memory).
**Evidence:** asm 00401160-004014f9 read in full (the decompile mixes stack offsets; the asm fixes the extra data offsets +6 / +8 and the in-memory record fields). Jump table at 004014fc.
**Port:** engines/tesoro/core/animbank.cpp::AnimBank::load (codex/fresh-core, uncommitted). Deviations: tables are heap arrays, not pool arenas; malformed or truncated data fails the load instead of overrunning; types 3 and 5+ keep no point data (the original leaves it uninitialised) and log a warning; a bank with no sequences does not touch a record 0.
**Validation:** Differential check `re/tools/run_startup_check.sh` (gen_vectors_anim.py + drivers/anim_driver.cpp): original Load/LoadImage/LoadDeferredImages/ScaleBrightness/SetRange run in Unicorn (fread/fgetpos/fseek/fsetpos, Archive_SeekEntry, the pool allocator and Clock_Now replaced by Python) on 700 synthetic animation files (0-9 sequences of types 0/1/2/4, 0-5 images of types 0/1/2/3/7, both pixel layouts, 5-5-5 and 5-6-5, load modes 0 and 2) vs engine AnimPlayer/AnimBank/AnimImage: load 700/700, header 700/700, flags 700/700, sequences 2509/2509, image positions 700/700, images after load 1396/1396, after deferred load 861/861, after brightness 832/832, SetRange 1748/1748. Five deliberate mutations of the port were all caught. Limits: synthetic data only (the shipped .DAT was not read); pool allocation/exhaustion is not modelled; the 5-5-5 overrun past the blob end and a sequence-less bank with images are not reproduced; pixel-first layouts are tested only without 5-5-5; item arrays shared by two spans are not tested; ranges reading past the sequence table are not tested.
**Open questions:** the second +4 skip; meaning of header +8/+0xc/+0x10 (copied into +0x32..+0x3d) and sequence fields +0, +4, +0xc, +0x10; what the sub-case "type 3" is (falls to default); whether reading uninitialised +0x1c matters in the shipped data.
**Audit (29 Oct 2026):** legacy reads the 4 bytes at the second skip as `ANM` + isFont byte and the three header dwords as a 12 byte name; consistent but unconfirmed on the real file. See AUDIT.md.
