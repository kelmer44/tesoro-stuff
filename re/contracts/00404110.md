# 00404110 — inferred_Sound_PlayWav
Status: understood · Cluster: 8 · Convention: thiscall(SoundDevice *this (global 00442080), uint32 archiveOffset, a, b, uint16 tag) — RET 0x10
**Behaviour:** takes the next of the device's stream records (+8 pointer array, count at +0x18, incremented), seeks the archive file (0x4032e0) to the entry, reads the 0x2c-byte header and accepts it only when it has "RIFF" at 0, "fmt " at 12, format 1 (PCM) at 20 and "data" at 36 (the plain 44-byte WAV header; checked: all 2,346 WAVs in the archive are PCM mono 22050 Hz 8 bit with exactly that header). Then the record gets the data size (header +40), the file position of the data (0x403300), loads the first buffer (0x4042c0), +0x24 := tag, active byte (+0x28) := 1, sets the DirectSound buffer's format through slots 0x30/0x3c/0x40 and returns a new id (device +0x14 incremented, stored in the record at +0x2c). On a bad header the record is still used but not loaded. Buffers: 0x5622 bytes (1 s) in two halves of 0x2b11, refilled by 0x4043e0 as the play cursor crosses halves; the unused tail is filled with 0x7f (8-bit silence is 0x80). Scripts call it with (offset of NAME.WAV, 0, 0, 0). **Port:** `SoundDevice` (core/sounddevice.cpp): gen_vectors_sound.py + drivers/sound_driver.cpp, 800 random sessions, 13,821 operations (play of valid and invalid headers, find by id, stop-and-tidy, update with finished sounds in the middle of the list) give identical ids, record order, loads and stops; 13 of 14 mutations caught (the other is a redundant reset). Not covered: the streaming of long sounds and the exact moment a voice ends (the mixer decides; the original ends a short sound when the play cursor reaches the data end and a long one up to half a buffer later). Found: the device has **three** records (a fourth simultaneous sound reads past its record array in the original; the port refuses it and returns id 0); a record stays in the active list until update() so a finished voice is still found for up to a frame; a file with a bad header still gets an id and makes no sound. The archive offsets already include the 4-byte size prefix (ArchiveIndex adds it); the WAV header is read there.
