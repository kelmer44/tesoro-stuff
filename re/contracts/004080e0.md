# 004080e0 — inferred_Level_Load
Status: emu-compared · Cluster: 13 · Convention: thiscall(Level *this, uint32 entryOffset, int mode) — RET 8; 0x13e8 byte frame

**Purpose (confirmed):** Constructor and reader of a scene file (.LVL). Builds the level object (base constructor 00401bc0, vtable 00428bf8) and fills it from the archive entry.
**Inputs:** entryOffset (from Archive_FindEntry; the function seeks to entryOffset + 4); mode = animation load mode (0 normal, 2 deferred images), passed to every AnimBank_Load. Reads the display's 5-5-5 flag through the bank loader.
**File layout (from entryOffset + 4):** header 0xc {+0 room count, +4 bank count, +8 total object count (only used to size lists)}; then the banks, back to back, each read by AnimBank_Load at the current stream position (it skips four bytes first and leaves the stream at the end of the bank); then for every room a 0x28 record {+0x20 u16 object count, +0x22 u16 extent, +0x24 u32 camera divisor, the rest is not read here} followed by its objects, each a 0x20 record {+0 i32 x, +4 i32 y, +8 i16 sort offset, +0xb u8 bank count, +0xc name (12 chars), +0x18 u32 kind, +0x1c u32 byte count N} then N bytes of kind data then bank-count bytes of bank indices.
**Outputs / state written (this):** +0x6c array of banks (AnimPlayer, 0x40 each, bank count entries); +0x70 array of rooms (0x10 each, Room_Ctor with the running sort offset: it starts at 0 and grows by each room's extent); +0x74 object list (handle to a list with capacity total+5; each object built by the factory 00409e50 gets byte +0x5c := kind and is appended with 0040f800); +0x78 a 0x34 byte list with capacity 0x32 (pairs queue of the collision pass, empty); +0x7c a plain list with capacity 0x14 (collidable objects that moved); +0x80 camera (0x40 bytes, Camera_Ctor, bounds -320, 239, 319, -240); +0x84 room count; +0x88 bank count; +0x8c := Clock_Now; +0x90 := the kind 1 object when the factory built one; +0x94 byte := 0. The objects are not put into their rooms' lists here (that happens in AttachObjects).
**Calls:** 004032e0, 0041b4c0, 0040db40, 0040f650, 0040f590, 00402110, 00401160, 00410420, 00409e50, 0040f800, 00402200, 00413a10, 00401bc0.
**Edge cases:** the record's +0x1c is the data size in the file and is passed on unchanged: the animated constructor 00401aa0 finds the bank indices at (data buffer + record +0x1c). Allocation failures are not checked. Names of 12 characters run on into the kind field when the hash reads the name as a string. Counts are not range checked (the port rejects more than 100000 and kind data above 0x1000 bytes; the original has a 0x1300 byte stack buffer).
**Evidence:** asm 004080e0-00408430 read in full (the decompile garbles the stack arguments); callers: InitGameWorld, 47 + 3 times.
**Port:** engines/tesoro/core/level.cpp::Level::load (codex/fresh-core). Deviations: lists have no capacity and no shared pool; the extra +0x78 list is not built (the collision pass is not ported); objects of kinds that are not ported yet are skipped with a warning, so +0x90 stays null; the kind byte is stored through Object::setKindId.
**Validation:** Differential check `re/tools/run_startup_check.sh` (gen_vectors_level.py + drivers/level_driver.cpp): the original Level_Load, AttachObjects, ObjectMoved, FindObjectByKey, CameraMoveTo and UpdateRoomCameras run in Unicorn (fread/fgetpos/fseek, Archive_SeekEntry, the pool allocators and Clock_Now replaced by Python; AnimBank_Load, Room_Ctor, the object factory and the animated object constructor run as in the executable) on 500 synthetic level files (0-3 rooms, 0-4 banks, up to 8 objects of kind 0 plus numbers the factory has no class for, 0-3 bank indices, 0-20 bytes of kind data, load modes 0 and 2, both pixel layouts, negative and large room divisors), then random ops: flags, attach, objectMoved, find, camera move, room camera update. After load and after every op the whole state is compared: camera dwords, moved list, each room (index, divisor, sort offset, extent, ordered object list), counts, banks, every object (key, kind byte, position, sort value, flags, room, previous position, its players): load 500/500, attach 296/296, moved 403/403, find 190/190, cameraMoveTo 589/589, updateRoomCameras 826/826 (with hit rectangle, moved area and shown sequence of every object). Deliberate mutations caught: sort offset ignoring the room extent, camera bounds, no collidable test, repeated appends, ignored processed or visible flag, wrong room stored, bank read position off by one, load time, list order, key high word, kind data not skipped. Not covered: kind byte and the kind 1 object (only kind 0 objects exist in the port, so the byte is always 0), the other kinds, names of 12 characters (the original hashes on into the kind field), node pool overflow, level files from the real archive.
**Open questions:** the meaning of the third header dword beyond list capacity; what Level_Load's loaded time is used for; whether the 12-character name overrun occurs in the shipped files.
