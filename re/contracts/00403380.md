# 00403380 — inferred_Archive_ReadIndex
Status: understood · Cluster: 3 · Depth: 3 · Convention: fastcall(Archive *this)

**Purpose (confirmed):** Reads the whole .TRE directory, keeps the data entries and sorts them so FindEntry can binary-search them.

**Inputs:** this+4 = open FILE* of the .TRE (positioned at its start).
**TRE record (0x1c bytes, read one at a time by fread(buf,0x1c,1)):** +0 uint32 offset, +4 uint32 (not used here, probably size), +8 flags byte, +9 name char[19] (NUL-terminated if shorter).
**Outputs / state written:** this+0 = number of kept entries. For each record whose flags has bit 2 (value 4) set, in file order: name is upper-cased in place (locale-aware strupr), copied to entry[n].name with strncpy(…, 0x13) then name[0x12] = 0; entry[n].offset (+0x14) = record.offset + 4. Entry layout (0x18 bytes): +0 char name[0x13], +0x13 unused, +0x14 uint32 offset. Records without bit 4 are skipped (not counted).
Reading stops when fread returns 0 or the stream EOF flag (0x10) is set before a read (a final record read exactly to EOF still counts, since the flag is only tested before the next read).
**Sort:** if count > 1, selection sort **descending** by name: for i in 0..count-2, find j in i+1.. with the largest key (strictly greater replaces, so the first maximum wins), swap entry i and entry j via 24-byte copies. Key compare is an unsigned byte compare up to the first NUL (strcmp order).
**Calls:** fread 0041b4c0, strupr 0041b940, strncpy 0041b840 (all CRT, replaced).
**Yields / blocks / timing:** none
**Edge cases:** No bounds check against the 2300-entry buffer. A name using all 19 bytes with no NUL would make strupr run past the record buffer (undefined; irrelevant for valid data). Offset +4 skips something at the start of each data block (4-byte header, unknown meaning). Duplicate names: relative order after the (unstable) selection sort is deterministic; a port should use the same algorithm if duplicates exist.
**Evidence:** export/00403380.c and asm 00403380-004034f5 (SBB/SBB compare, `JLE` keeps first max). FindEntry's search direction is consistent with descending order.

**Validation:** none
