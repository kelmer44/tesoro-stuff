# 00412c50 — inferred_Display_Compose_Overlay (queued text)
Status: understood · Cluster: 32 · Convention: thiscall(Display *this, TextEntry *entry)
**Behaviour (read, not ported):** draws one queued text (entry 0x70 bytes: string at +0, colour u16 at +0x6c, font index u16 at +0x6e, position row +0x68 and column +0x64) straight into the locked frame: for each character (code − 0x21 picks the glyph sequence of the font bank), copies the glyph rows (literal glyph images by copy, type-3 glyphs as the colour or zero), advancing by the glyph width + 2 pixels; a code of 0x7f (index 0x5e) draws nothing and only advances.
**Details found by comparing:** the glyph is placed `font space glyph imageY - glyph imageY` rows below the line's y, advances by the image's own width + 2 (not the width used by the layout), glyph 94 (0x7f) is not drawn; type 3 items with value 0 write black, others the line's colour; a glyph past the right edge continues on the next row (the frame is linear).
**Port:** `TextQueue::draw`, called at the end of `ScreenDisplay::compose`. **Validation:** see 00411c80 (192,000 frame rows identical over a solid background; fonts of 95-190 literal and solid glyphs). Deviation: writes outside the frame are dropped.
